# trendai — 과거 → 현재 → 미래, 트렌드를 읽고 예측하는 AI

어떤 시계열이든 넣으면(검색 관심도, 위키백과 조회수, 매출, 가격, KPI 등) **trendai**가

1. **과거**: 장기 추세·계절성을 분해하고, 추세가 꺾이거나 가속한 **구조 변화 시점**과 이상치를 찾고,
2. **현재**: 트렌드가 지금 **수명주기의 어디**(태동기·성장기·정점·쇠퇴기·안정기·재부상·변동성)에 있는지와 모멘텀을 진단하고,
3. **미래**: 여러 예측 모델을 과거 데이터로 **백테스트해 자동으로 고르고 앙상블**해서 예측값과 **불확실성 구간(80%/95%)**, 상승 확률, 시나리오를 내고,
4. **해석**: 이 모든 것을 사람이 읽을 수 있는 한국어(또는 영어) 리포트로 설명합니다. 원하면 **Claude**가 해석문을 쓰고 질문에 답합니다.

결과는 터미널 요약, **HTML 리포트**(차트 포함, 단일 파일), JSON으로 받을 수 있습니다.

## 빠르게 써보기

```bash
# 내장 합성 샘플(가상 데이터)로 데모
python -m trendai list-samples
python -m trendai sample emerging --html out/emerging.html
python -m trendai sample all --html out/compare.html        # 9가지 트렌드 유형 비교·순위 (+ 개별 리포트)

# 내 데이터 (CSV/TSV/TXT/Excel/JSON — 인코딩·구분자·날짜 열·숫자 열을 자동 감지)
python -m trendai analyze data.csv --horizon 12 --html report.html --json report.json
python -m trendai analyze data.csv --value-col 검색량 --freq M
python -m trendai analyze data.csv --date-col 날짜 --value-col 검색량 --value-col 판매량

# 여러 시계열을 비교해서 '뜨는 트렌드' 순위 매기기 (주기가 달라도 연환산해서 비교)
python -m trendai compare a.csv b.csv --html compare.html
python -m trendai compare a.csv --samples emerging,fad

# 온라인 데이터 (인터넷 필요)
python -m trendai wiki "인공지능" "메타버스" --html wiki.html      # 위키백과 월별 조회수
python -m trendai trends "생성형 AI" --geo KR                      # Google Trends (pytrends 필요)

# Claude가 해석문을 작성 / 분석 결과에 대해 질문
export ANTHROPIC_API_KEY=...        # 또는 `ant auth login`
python -m trendai analyze data.csv --llm
python -m trendai ask data.csv "앞으로 6개월 동안 어떻게 될까? 위험 요인은?"
```

CSV 예시 (값 열이 여러 개면 각각 분석하고 비교 순위까지 만듭니다):

```csv
날짜,검색량,판매량
2023-01,120,40
2023-02,135,38
...
```

- 시계열이 하나면 해석문까지 출력하고 HTML 리포트 1개를 씁니다. 여러 개면 요약 + 순위를 출력하고
  (해석문은 HTML/JSON에 들어 있음), `--html out.html`이면 비교 페이지 `out.html`과 개별 리포트
  `out_<이름>.html`을 씁니다. `--json`은 시계열 1개면 객체, 여러 개면 배열입니다.
- `--horizon`(`-H`)을 생략하면 일 30일·주 26주·월 12개월·분기 8분기·연 5년을 예측합니다.
- 해석문은 터미널에서 Markdown 기호(`##`, `**`) 없이 보여 주고, 파일로 저장하면(`> out.txt`) Markdown 그대로 씁니다.
- `--lang en`은 해석문·터미널 요약·CLI 안내 문구, 명령줄 인자 오류, 데이터 오류·경고·안내, 온라인 조회(`wiki`·`trends`)
  오류를 영어로 바꿉니다(접두어도 `Note:`·`Warning:`·`Data error:`). JSON의 국면 근거(`phase.reasons`)도 영어가 되고
  한국어 원문은 `phase.reasons_ko`에 남습니다. HTML 리포트는 한국어입니다.
- 데이터를 읽으면서 바꾼 점은 stderr에 한 줄씩 알려 줍니다: `안내:`(어떻게 해석했는지 — 감지한 날짜 열·형식,
  제외한 행 번호 열, 모호한 일/월 순서 등), `경고:`(값을 버리거나 메운 경우 — 읽을 수 없는 값, 보간한
  빈 기간, 평일만 있는 데이터, 분석에 실패한 시계열, `--freq`로 데이터보다 촘촘한 주기를 지정해(월별 데이터를
  `--freq W`로) 대부분의 기간을 보간한 경우 등).
- 종료 코드: `0` 성공, `1` 실행 실패(네트워크·Claude·파일 저장·예기치 못한 오류), `2` 입력 오류(파일·데이터·인자).

### 읽을 수 있는 데이터

| 항목 | 지원 형식 |
|---|---|
| 파일 | `.csv` `.tsv` `.txt`(구분자 `,` `;` 탭 `\|` 자동 감지), `.xlsx`(openpyxl), `.xls`(xlrd), `.json`(레코드 목록, `{날짜: 값}`, `DataFrame.to_json()`의 columns/index/split/table, JSON Lines) |
| 인코딩 | UTF-8(BOM 유무), UTF-16(엑셀 "유니코드 텍스트"), CP949/EUC-KR(한국어 엑셀·공공데이터) |
| 날짜 | `2024-01-05`, `2024-01`, `2024.01`·`2024. 1. 5.`(KOSIS·한국어 엑셀), `202401`·`20240105`(ECOS), `2024년 1월`, `2024년 1분기`·`2024 1/4분기`, `2024 Q1`·`2024Q1`·`Q1 2024`, `2024-W01`(ISO 주), `05.01.2024`·`01/05/2024`(일/월 순서는 열 전체를 보고 한 번에 결정, 모호하면 안내), `Jan 2024`, 연도(순서·중복 무관), Unix 초/밀리초, 시간대 오프셋이 붙은 시각(현지 시각 유지) |
| 숫자 | `1,234`, `1.234,5`(소수점 쉼표, `;` 구분 CSV), `1 234`, `12%`, `$1,234`, `1,234원`, `(1,234)`(음수), `1.2억`·`3,400만`·`12K`·`1.5M`, 결측 표시 `-` `NA` `#N/A` 등 |
| 표 모양 | 날짜 열 1개 + 값 열 N개(세로형), `연도` 열 + `월`(또는 `분기`) 열, 날짜가 열 머리글에 놓인 가로형(KOSIS 기본), 머리글 없는 파일 |
| 제외하는 열 | `Unnamed: 0`(`DataFrame.to_csv()`의 행 번호), `id`·`no`·`번호`·`순번`, 0·1부터 1씩 증가하는 정수 열 (`--value-col`로 지정하면 포함) |

평일(영업일)만 있는 데이터(주가 등)는 주말을 보간해 달력일 기준으로 분석하며 이를 경고로 알립니다
(주 단위로 보려면 `--freq W`). 주간 데이터는 원래 요일(예: 월요일)을 유지하고 예측 날짜도 그 요일로 이어집니다.

## 결과 읽는 법

`python -m trendai sample emerging`의 터미널 요약 중 일부입니다.

```text
[태동기(신흥)] 신뢰도 95% · 월 단위 120개 · 2016-01 ~ 2025-12
현재 값 69.9 · 전체 변화 +1,365% · CAGR +31.1% · 최근 변화 +68.5%
모멘텀 +3.91%p/월 · 변동성 8.5%
전망 ▲ 상승 · 예측 변화 +45.4% (향후 12개월 평균, 최근 12개월 평균 대비)
상승 확률 96% (같은 기준) · 신뢰도 높음
시나리오(2026-12 시점)  비관 72.1  기준 91.2  낙관 110.2  (비교: 현재 69.9)
정확도: 단순 예측 대비 오차 −64% · 단순 예측보다 정확 · MASE 1.34
```

| 표시 | 뜻 |
|---|---|
| `[태동기(신흥)] 신뢰도 95%` | 수명주기 국면과 그 판단을 얼마나 확신하는지(해석문의 '판단 신뢰도'). 통계의 신뢰수준이 아니며, 아래의 예측 신뢰도·80%/95% 구간과도 다른 숫자입니다. 근거는 해석문 '현재' 절에 있습니다 |
| `전체 변화`·`CAGR`·`최근 변화` | 추세선 기준의 처음→끝 변화, 연평균 성장률, 최근 한 주기(월별이면 12개월) 변화. `—`이면 바로 아래 `※` 줄에 이유가 있습니다 |
| `모멘텀 +3.91%p/월` | 최근 추세 기울기와 장기 기울기의 차이를 현재 추세 수준 대비 %로 나타낸 값. +면 장기 평균보다 빨리 오르는 중(가속), −면 둔화 |
| `변동성 8.5%` | 추세·계절로 설명되지 않는 잔차의 변동계수 |
| `전망 ▲ 상승` | ▲ 상승, ▼ 하락, ▶ 보합(변화가 2% 미만) 또는 ▶ 방향 불확실(변화가 2% 이상이지만 예측 불확실성에 비해 작아 방향을 단정할 수 없음) |
| `예측 변화 +45.4%` | 예측 마지막 한 주기의 평균(향후 12개월 평균)을 최근 한 주기의 평균(최근 12개월 평균)과 비교한 값. 특정 시점 한 값의 변화가 아닙니다 |
| `상승 확률 96%` | 같은 두 평균에서 미래 평균이 더 높을 확률 |
| `신뢰도 높음` | 예측 신뢰도(높음·보통·낮음): 백테스트 정확도, 데이터 길이, 예측 구간 폭으로 정합니다 |
| `시나리오 비관·기준·낙관` | 예측 마지막 시점(여기서는 2026-12) 한 값의 80% 구간 하한·예측값·상한. 평균끼리 비교한 예측 변화와는 다른 양이라, 해석문의 '기준 91.2 (+30.4%)'(현재 값 대비)와 '+45.4%'가 다릅니다 |
| `정확도: 단순 예측 대비 오차 −64%` | 과거 구간 백테스트에서 단순 예측(직전 값 유지·계절 반복·추세 연장 중 가장 나은 것)보다 오차가 64% 작았다는 뜻. MASE는 기술 지표라 1과 비교하지 마세요 |
| `상위 모델(MASE)` | 백테스트 순위가 높은 모델. 괄호 안은 모델 ID입니다(`로지스틱 S-커브(logistic_growth) 1.34`) |
| `변화 강도 0.49` | 해석문의 구조 변화 항목: 기울기 변화가 다음 구간 동안 만든 수준 차이를 시계열 규모로 나눈 값(단위 없음, 클수록 큰 전환) |
| `점수 92.4` | 비교 순위의 상승 점수(0–100, 50 = 중립). 전망(예측 변화·상승 확률)과 최근 기세(최근 변화·모멘텀)를 합친 값이라 그 자체가 예상 상승률은 아닙니다 |

HTML 리포트의 'AI 트렌드 해석' 옆 배지는 해석문을 쓴 주체입니다: 기본은 `규칙 기반 해석`, `--llm`이면 `AI(Claude) 해석`.

판단 순서:

1. **방향** — `전망`과 `예측 변화`: 오르는지, 내리는지, 보합인지.
2. **확률** — `상승 확률`: 90% 이상(10% 이하)이면 방향이 꽤 분명하고, 45–55%면 어느 쪽이라고 말하기 어렵습니다.
3. **폭** — 시나리오(80% 구간)와 예측 신뢰도: 비관~낙관 폭이 넓거나 신뢰도가 낮으면 숫자 하나보다 구간으로 판단하세요.

## 파이썬에서 사용

```python
from trendai import run, run_many, rank_trends, load_table, render_html, render_compare_html

series = load_table("data.csv")["검색량"]      # 또는 아무 pd.Series (DatetimeIndex·PeriodIndex·연도 정수 인덱스)
report = run(series, horizon=12)

report.analysis.phase.label_ko          # '성장기'
report.analysis.changepoints            # 구조 변화 시점들
report.analysis.metrics.cagr_pct        # 연평균 성장률 (None일 때의 이유: trendai.narrative.metric_pct_undefined(report.analysis))
report.forecast.to_frame()              # 예측값 + 80/95% 구간
report.forecast.skill                   # 백테스트 오차 / 최선 나이브 오차 (MAE, 간헐 수요는 RMSE; <1이면 나이브보다 정확)
report.outlook.prob_increase            # 상승 확률 (의미 없을 때의 이유: trendai.narrative.prob_undefined(report.analysis))
print(report.narrative)                 # 과거/현재/미래 해석
render_html(report, "report.html")

reports = run_many(load_table("data.csv"))   # {이름: TrendReport}, 실패한 시계열은 경고 후 건너뜀
ranking = rank_trends(reports)               # 상승 트렌드 순위 (pandas DataFrame)
print(ranking[["name", "phase_ko", "expected_change_ann_pct", "prob_increase", "score"]])
render_compare_html(list(reports.values()), ranking, "compare.html")
```

- 입력을 쓸 수 없으면 `trendai.DataError`, 데이터를 고쳐서 쓴 경우 `trendai.DataWarning`,
  해석 방식 안내는 `trendai.DataNotice` 경고가 발생합니다. 메시지의 `str()`은 한국어, `exc.text('en')`은 영어이며
  `exc.code`·`exc.params`로 종류를 구분할 수 있습니다.
- `load_table`이 돌려준 시계열의 `series.attrs["trendai"]`에 감지한 날짜 열·형식이 들어 있습니다.
- JSON(`--json`, `trendai.report_to_json(report)`)의 `metrics.pct_undefined`는 %로 나타내지 않은 지표와 그 이유
  (`{"total_change_pct": "at_zero"}` 등, 해당 지표는 `null`)이고, `synthetic`은 내장 합성 샘플이면 `true`입니다.
  `report_to_json(report, lang="en")`은 국면 근거를 영어로 씁니다.
- 순위 점수(rising score, 0–100, 50=중립)는 예상 변화·상승 확률·최근 변화·모멘텀을 섞되, 변화율은 연환산하고
  모멘텀은 월 기준으로 맞춰 일·주·월·분기 데이터를 공정하게 비교합니다. 표에는 각 리포트의 원래 값
  (`expected_change_pct` 등)과 점수 계산에 쓴 연환산 값(`expected_change_ann_pct`, `recent_change_ann_pct`,
  `momentum_per_month`)이 함께 들어 있습니다.

## Claude 연동 메모

- `--llm`/`ask`는 공식 `anthropic` SDK로 `claude-opus-5-5`를 호출합니다. 모델에는 **계산된 사실(JSON)만** 전달하고, 주어진 사실 밖의 사건을 단정하지 말고 불확실성을 밝히도록 지시합니다.
- 안전 분류기 거절 시 서버 측 대체 모델로 자동 재시도하는 `fallbacks="default"`(베타 `server-side-fallback-2026-07-01`)가 켜져 있습니다.
- `--llm`은 키가 없거나 호출이 실패하면 자동으로 규칙 기반 해석으로 대체하고(stderr에 이유 안내), `ask`는 답할 모델이 없으므로 오류 메시지와 함께 종료 코드 1로 끝납니다.

## 한계와 주의

- 예측은 과거 패턴이 이어진다는 가정에 기반합니다. 시계열 하나만 보므로 정책·사건 같은 외부 충격이나 가격·광고·휴일 같은 외부 변수는 반영되지 않으며, 예측 구간은 먼 미래일수록 넓어집니다.
- 예측 구간은 백테스트로 보정하지만, 관측치가 아주 적거나 구조 변화가 막 일어난 시계열에서는 실제 포함률이 80%/95%보다 낮을 수 있습니다.
- 주기는 일·주·월·분기·년만 지원합니다. 영업일(`B`) 주기가 없어 평일만 있는 데이터는 주말을 보간해 달력일로 분석하고(경고로 안내), 시간 단위 데이터는 일 평균으로 합칩니다. 일별 데이터는 요일 주기(7일)만 반영하며 연간 계절성은 모델링하지 않습니다.
- 관측치가 약 8개보다 적으면 백테스트 없이 예측합니다. 추세가 통계적으로 유의하면 드리프트와 직전값을 평균하고, 아니면 직전값을 유지하며, 구간은 넓게 잡습니다. 수명주기 단계는 잠정 판단으로만 표시하고, 구조 변화·이상치 탐지도 8개 이상부터 합니다. 짧거나 주기가 적은 시계열(예: 분기 40개, 월 36개, 연 30개)에서는 중간 크기(4–5σ)의 일회성 급등이 이상치로 잡히지 않을 수 있습니다.
- 변화율(%)은 의미가 있을 때만 냅니다. 기준값이 0에 가깝거나(음수가 있는 데이터는 표준편차의 절반 이내) 음수인 경우, 그사이 0을 지나 부호가 바뀐 경우(예: 손익이 흑자에서 적자로)에는 %를 내지 않고 이유와 함께 단위 값으로 보여 줍니다. 예측 변화도 같은 규칙이라 현재 수준이 음수이면 두 수준을 단위 값으로 비교합니다. 이상치의 '예상 대비 %', 평균 수준 대비 기울기·모멘텀·변동계수도 같은 이유로 빠집니다. 한두 개의 극단값(예: 1,000,000)은 '0에 가깝다'를 판단하는 기준 수준에서 제외합니다. 음수가 될 수 없는 시계열이 0(또는 이전 수준의 0.05% 이하)까지 떨어지면 −100% 대신 `추세선 기준으로 5.00에서 0까지 떨어졌습니다`처럼 도달한 수준을 말하고(요약과 HTML은 `추세가 0 수준까지 떨어져 변화율 없음`), 낙폭은 고점을, 예측은 `예측이 하한인 0까지 내려가`로 알려 줍니다.
- 0이 많은 간헐 수요와 관측값이 모두 0인 시계열은 추세 기반 변화율(전체·최근 변화, CAGR)과 수준 대비 %를 내지 않고, 국면 근거도 단위 값으로 말합니다. 과거는 처음과 최근 1년(또는 한 주기)의 평균 수요량으로 설명하고, 평소 주문 간격보다 훨씬 길게 0이 이어지면 그 사실을 알립니다. 예측 변화는 평균 수요량끼리 비교하며, 최근 한 주기의 절반 이상이 0이면 내지 않습니다. 모두 0이거나, 예측이 정확히 0이거나, 최근 한 주기가 모두 0이라 더 내려갈 수 없는 시계열은 상승 확률도 내지 않습니다(JSON에서는 `prob_increase`가 `null`이고 `prob_increase_undefined`가 이유). 큰 주문 한 건만으로는 성장·쇠퇴 국면으로 판단하지 않습니다. 간헐 수요의 상승 확률은 주문이 생길 확률과 과거 주문 크기의 분포로 계산하고, 전망은 변화가 2%를 넘고 그 확률이 2/3를 넘을 때만 상승(1/3 미만일 때만 하락)으로 봅니다. 평균 수요량은 큰 주문 몇 건에 끌려 올라가므로, 예측 변화가 +일 때도 상승 확률이 50%를 조금 밑돌 수 있습니다(예: `+10.9%`에 상승 확률 44%, `방향 불확실`). 이 확률은 예측한 수요량만큼만 믿을 수 있어, 짧은 시계열에서는 실제보다 확신 있게 나오기도 합니다.
- 수명주기 단계는 합성 샘플 유형으로 검증한 규칙 기반 판단이라 참고용으로 보세요.
- HTML 리포트와 명령줄 도움말(`--help`)은 한국어로만 나옵니다. 라이브러리에서 받는 예외·경고의 `str()`은 한국어이고, 영어 문구는 `exc.text('en')`로 얻습니다.
- `wiki`·`trends`는 인터넷 연결이 필요하고, Google Trends는 `pytrends`가 있어야 하며 요청 제한에 걸릴 수 있습니다. Claude 기능은 API 키가 필요합니다(`--llm`은 호출에 실패하면 규칙 기반 해석으로 대체하고, `ask`는 오류로 끝납니다).
- 내장 샘플은 **합성 데이터**입니다(실제 데이터 아님). 터미널에는 `※ 합성(가상) 샘플 데이터입니다`, HTML에는
  `합성(가상) 샘플 데이터` 표시, JSON에는 `"synthetic": true`가 붙습니다(`compare --samples`로 섞은 경우도 같음).
- 투자·사업 판단의 유일한 근거로 쓰지 마세요.
